一、C语言基础
-------------------------------------

Q1: volatile 关键字的作用是什么？什么场景下需要使用它？

参考答案：
volatile 告诉编译器"这个变量的值随时可能被意外改变"，禁止编译器对它进行优化，每次访问都必须从内存中读取。

使用场景：
- 外设寄存器：硬件寄存器值可能随时被硬件改变（如状态寄存器）
- 多线程共享变量：多个任务/中断共享的全局变量
- 中断服务程序修改的变量

示例：
    volatile uint32_t *const STATUS_REG = (volatile uint32_t *)0x40021000;
    if (*STATUS_REG & 0x01) {  // 必须每次从外设读取
        // ...
    }


Q2: 什么是结构体对齐？为什么要对齐？如何手动控制？

参考答案：
编译器为结构体成员分配地址时，会按照某个对齐系数（通常为4或8）进行填充。

为什么要对齐：CPU 访问效率更高（32位CPU一次读4字节，未对齐需要两次读）。

手动控制对齐：

方法1：调整成员顺序（最常用）
    struct A {
        uint8_t a;    // 1字节
        uint32_t b;   // 4字节 -> 放最后减少填充
        uint16_t c;   // 2字节
    };  // 总大小: 8字节 (而不是12)

方法2：使用 #pragma pack
    #pragma pack(1)  // 1字节对齐，无填充
    struct B {
        uint8_t a;
        uint32_t b;
    };  // 总大小: 5字节
    #pragma pack()

方法3：__attribute__((aligned(n)))
    struct C {
        int a;
    } __attribute__((aligned(64)));  // 对齐到64字节边界


Q3: static 关键字在局部变量和全局变量中的作用分别是什么？

参考答案：
- 局部变量加static：函数退出时不释放，值保留到程序结束。只初始化一次。
- 全局变量/函数加static：限制作用域，只在本文件内可见（内部链接）。

示例：
    void counter() {
        static int count = 0;  // 只初始化一次，调用之间保持值
        count++;
    }

    // static 全局变量：类似"私有"成员
    static uint8_t g_internal_state;  // 只能在本.c文件访问

二、RTOS（FreeRTOS）相关
-------------------------------------

Q5: FreeRTOS 中任务有哪些状态？状态之间如何切换？

参考答案：
任务有4种状态：

        运行状态(Running)
             |
    (调度器选出其他更高优先级任务)
             v
        就绪状态(Ready)
       /           \
      v              v
  阻塞状态      挂起状态
  (Blocked)    (Suspended)

- Running：正在运行
- Ready：就绪，等待调度
- Blocked：阻塞（等待信号量/队列/延时到期）
- Suspended：挂起（vTaskSuspend，需手动恢复）


Q6: 什么是优先级反转？如何解决？

参考答案：
高优先级任务等待低优先级任务释放资源，但低优先级任务被中间优先级任务抢占了CPU，导致高优先级任务反而更晚完成的现象。

时间线示例：
低优先级任务(L) 持有锁 -> 被中优先级任务(M)抢走CPU -> L无法运行 -> 无法释放锁 -> 高优先级任务(H)一直被阻塞

三种经典解法：
1. 优先级继承：临时提升低优先级任务的优先级
2. 优先级天花板：一次性把优先级提到最高
3. 禁止中断：关键区不允许抢占

面试加分回答：
"在智能手表项目中，我使用了互斥量（xSemaphoreCreateMutex）来保护MPU6050等共享传感器，因为互斥量自带优先级继承机制，避免了优先级反转问题。"


Q7: 消息队列和二值信号量的区别是什么？分别在什么场景使用？

参考答案：

对比项        | 消息队列              | 二值信号量
--------------|----------------------|------------------
传输内容      | 有具体数据（可携带信息）| 只有"可用/不可用"状态
数据量        | 可发送任意类型数据     | 只传递1bit信息
阻塞等待      | 可指定超时等待和阻塞数量| 同上

使用场景：
- 消息队列：gps任务 -> 将GPS数据放入队列 -> UI任务取出显示
- 二值信号量：中断触发标志，中断释放信号量 -> 任务等待信号量处理

示例：
    // 消息队列（帧数据传递）
    QueueHandle_t frame_queue = xQueueCreate(5, sizeof(camera_frame_t));
    // Core1 摄像头采集完成后发送
    xQueueSend(frame_queue, &frame, portMAX_DELAY);
    // Core0 AI推理任务接收
    xQueueReceive(frame_queue, &frame, portMAX_DELAY);

    // 二值信号量（中断同步）
    SemaphoreHandle_t uart_semaphore;
    // 中断中
    BaseType_t higher_task_woken;
    xSemaphoreGiveFromISR(uart_semaphore, &higher_task_woken);
    // 任务中
    xSemaphoreTake(uart_semaphore, portMAX_DELAY);


Q8: 你的智能手表项目里有10+个任务，请说明你如何划分优先级的？为什么？

参考答案：
"我的优先级划分原则是：越高实时性要求的任务优先级越高，同时避免优先级相等导致频繁切换开销。"

优先级划分参考：

优先级  | 任务                   | 理由
--------|----------------------|----------------------------------------
高(4)   | 中断服务（I2C/SPI完成、按键、传感器数据就绪） | 硬件事件必须快速响应
中(5)   | MPU6050计步任务、心率采集任务 | 需要周期性运行
中(6)   | 消息队列发送任务        | 传递实时数据
低(7)   | UI刷新任务             | 对实时性要求较低，阻塞等待信号量
最低(8) | 低功耗管理任务、看门狗喂狗 | 后台任务

加分点：
- 相近功能的任务尽量放在同一优先级，使用时间片轮转，避免频繁上下文切换


三、通信协议
-------------------------------------

Q9: I2C 和 SPI 的区别是什么？各自优缺点？

参考答案：

对比项    | I2C                    | SPI
----------|----------------------|----------------------------------
总线类型  | 半双工，两线制（SCL+SDA）| 全双工，四线制（SCK/MOSI/MISO/CS）
速度      | 标速100kHz/快速400kHz/高速3.4MHz | 可达数十MHz
从设备数  | 多个（通过地址寻址）     | 每个从设备需独立CS线，线多
时钟      | 主设备提供（同步）       | 主设备提供（同步）
数据有效性| SCL高电平时采样         | SCL上升沿/下降沿采样（可配置）
流控      | 支持应答位(ACK/NACK)   | 无，需软件处理

各自适用场景：
- I2C：适合挂载多个低速外设（传感器）
- SPI：适合高速设备（显示屏、存储芯片）

项目中应用：
- I2C：MPU6050、AHT21（多字节连续读写，有设备地址）
- SPI：LCD屏幕（高速通信）


Q10: I2C 通信中出现死锁（SDA一直为低）的原因？如何处理？

参考答案：

原因：
- 从设备在发送数据时拉低SDA，但未发送完成
- 主设备发送数据后，从设备不应答但也未释放SDA
- 中断打断I2C操作导致总线状态不一致

处理方法：

方法1：软件模拟I2C强制复位
    void I2C_Recovery(void) {
        // 拉低SCL -> 发送9个时钟脉冲 -> 让从设备释放SDA
        for (int i = 0; i < 9; i++) {
            HAL_GPIO_WritePin(I2C_SCL_PORT, I2C_SCL_PIN, GPIO_PIN_RESET);
            delay_us(5);
            HAL_GPIO_WritePin(I2C_SCL_PORT, I2C_SCL_PIN, GPIO_PIN_SET);
            delay_us(5);
            if (HAL_GPIO_ReadPin(I2C_SDA_PORT, I2C_SDA_PIN) == GPIO_PIN_SET) {
                break;  // SDA恢复高，死锁解除
            }
        }
        // 发送STOP
        HAL_GPIO_WritePin(I2C_SDA_PORT, I2C_SDA_PIN, GPIO_PIN_RESET);
        delay_us(5);
        HAL_GPIO_WritePin(I2C_SCL_PORT, I2C_SCL_PIN, GPIO_PIN_SET);
        delay_us(5);
        HAL_GPIO_WritePin(I2C_SDA_PORT, I2C_SDA_PIN, GPIO_PIN_SET);
    }

方法2：使用硬件I2C超时检测 + 重新初始化


四、STM32 / ESP32 硬件相关

Q11: STM32 启动过程是怎样的？（从复位到main函数）

参考答案：

1. 复位后，PC指针 = 0x00000000（实际映射到Flash起始地址）
2. 从0x00000000读取栈顶指针(MSP)，放入R13(SP)
3. 从0x00000004读取复位向量(Reset_Handler地址)，放入PC
4. 执行Reset_Handler:
   a. 调用SystemInit()（配置PLL、时钟）
   b. 复制.data段(已初始化全局变量)到RAM
   c. 清零.bss段
   d. 调用__libc_init_array（执行C++构造函数等）
   e. 调用main()

加分回答：
"对于OTA升级，还需要区分从BootLoader跳转还是从App区启动，BootLoader负责更新向量表偏移。"


Q12: 你在智能手表中设计了"运行-睡眠-关机"三级功耗模式，请详细说明实现细节。

参考答案：
"三级功耗模式的设计思路是：根据用户交互状态，选择最低满足需求的功耗模式。"

    typedef enum {
        PWR_RUNNING,     // 正常运行模式，100MHz全速
        PWR_SLEEP,       // 浅睡眠，进入STOP模式，~800uA
        PWR_SHUTDOWN     // 深度关机，~10uA
    } PowerMode_t;

    // 运行 -> 睡眠 切换
    void Enter_Sleep_Mode(void) {
        // 关闭不需要的外设时钟
        __HAL_RCC_TIM2_CLK_DISABLE();

        // 配置外部中断唤醒（MPU6050运动中断）
        // ... 中断配置 ...

        // 进入STOP模式
        HAL_PWR_EnterSTOPMode(PWR_LOWPOWERMODE_STOP, PWR_WAKEUP_PIN_ANY);

        // 唤醒后重新配置时钟
        SystemClock_Config();  // HSE + PLL恢复100MHz
    }

    // 睡眠 -> 关机 切换
    void Enter_Shutdown_Mode(void) {
        // 保存关键状态到RTC Backup寄存器
        HAL_RTCEx_BKUPWrite(&hrtc, RTC_BKP_DR1, current_step_count);

        HAL_PWR_EnterSHUTDOWNMode();  // 最低功耗
    }

功耗数据：
- 正常运行：~30mA
- STOP模式：~800uA（相比运行降低97%+）
- 关机模式：~10uA

Q14: LVGL 的渲染机制是怎样的？如何避免UI卡顿？

参考答案：
"LVGL 是一个事件驱动的图形库，渲染不是实时的，而是基于 lv_timer_handler() 周期性检查需要重绘的区域。"

LVGL 渲染流程：
1. lv_timer_handler() 被定时调用（默认5ms）
2. 检测是否有对象属性改变需要重绘
3. 合并无效区域（避免重复绘制）
4. 执行实际渲染到显示缓冲区
5. 通过DMA/SPI发送到大屏

避免卡顿的建议：

1. 减少主循环中耗时操作
    while (1) {
        lv_timer_handler_run_in_period(5);  // 保持5ms调用
        // 耗时的处理放到低优先级任务
        if (data_ready) {
            xQueueReceive(data_queue, &data, 0);
            lv_obj_invalidate(my_label);  // 标记需要刷新
        }
    }

2. 使用双缓冲区避免撕裂
    lv_disp_draw_buf_init(&disp_buf, buf1, buf2, MY_HOR_RES * 10);

3. 减少动画对象数量，使用opa_scale等简单属性动画

Q15: 你的 ESP32-S3 双核任务分配策略是怎样的？为什么这样划分？

参考答案：
"ESP32-S3 有两个CPU核心，我根据任务的实时性要求和计算量来分配。"

Core 0（负责计算密集型任务）：
- Task 1: AI推理任务（人脸检测）    [高优先级]
- Task 2: LCD显示任务              [中优先级]
- Task 3: 消息队列消费者           [等待Core1数据]

Core 1（负责数据采集任务）：
- Task 4: 摄像头采集 (DVP)           [高优先级，硬件触发]
- Task 5: I2S音频采集 (麦克风)       [高优先级]
- Task 6: WiFi/BT 协议栈            [系统保留]

消息队列：Core1发送 -> Core0接收

回答要点：
"摄像头DMA采集具有实时性，必须在Core1；AI推理计算量大，在Core0独占；两边通过帧队列同步，避免Core1过快覆盖数据。"


Q16: OTA升级的完整流程是怎样的？如何保证OTA升级的安全性？

参考答案：
"OTA升级分为BootLoader、升级包传输、固件校验、跳转执行四个阶段。"

OTA 完整流程：
Step 1: BootLoader启动
        检查是否有待升级标志位
              |
              v
Step 2: BLE接收新固件
        Ymodem协议传输到Flash
        写入 APP2 分区
              |
              v
Step 3: 固件校验
        校验 CRC/SHA256签名
        验签通过才允许更新
              |
              v
Step 4: 更新启动标志位
        切换到 APP2 分区启动
        设置回滚标志（支持恢复）

安全保证：
1. 分区隔离：BootLoader区 + App1区 + App2区 + 配置区
2. 签名验证（防篡改）：使用RSA/ECC验签
3. 完整性校验：计算并比对CRC
4. 启动验证（防止变砖）：设置ESP_OTA_IMG_PENDING_VERIFY状态


Q17: 你的BootLoader和App之间如何跳转？跳转时需要注意什么？

参考答案：

    typedef void (*AppEntry_t)(void);

    void Jump_To_App(uint32_t app_address) {
        // 1. 禁止所有中断
        __disable_irq();

        // 2. 关闭外设（可选）
        HAL_RCC_DeInit();
        HAL_DeInit();

        // 3. 重设栈顶指针（App的向量表第一项）
        uint32_t stack_top = ((uint32_t *)(app_address))[0];
        uint32_t jump_addr  = ((uint32_t *)(app_address))[1];

        // 4. 配置MSP
        __set_MSP(stack_top);

        // 5. 跳转到Reset_Handler
        AppEntry_t App_Jump = (AppEntry_t)jump_addr;
        App_Jump();
    }

关键点：
- 跳转前必须禁止中断并关闭已初始化的外设
- App区的链接脚本需要指定正确的起始地址
- App区的 system_stm32f4xx.c 需要偏移向量表：SCB->VTOR = APP_ADDRESS

Q20: 你在项目中遇到的最大技术挑战是什么？如何解决的？

参考答案（结合你的项目）：
"我觉得最大的挑战是ESP32-S3双核之间数据一致性问题和智能手表的低功耗优化。"

挑战1：双核帧数据同步导致花屏
- 表现：LCD显示撕裂（半帧旧数据+半帧新数据）
- 排查：发现Core0在读取帧数据时，Core1同时在写入
- 解决：引入 xSemaphoreCreateMutex() 保护共享帧缓冲区

挑战2：STOP模式唤醒后系统时钟丢失
- 表现：进入STOP后功耗正常，但唤醒后系统工作在HSI（8MHz）而非PLL（100MHz）
- 排查：STOP模式下PLL会被关闭，WakeUp后需要重新配置
- 解决：在WakeUp中断回调中重新调用 SystemClock_Config()

面试技巧小贴士
=====================================

1. STAR法则回答项目问题：
   Situation（背景）-> Task（任务）-> Action（行动）-> Result（结果）

2. 数据化表达：
   不要说"做了优化"，要说"待机功耗从30mA降到800uA，降低了97%"

3. 诚实回答：
   不懂的问题可以说"这个我没深入了解过，但我认为..."，
   展现思路比装懂更重要

4. 反问环节准备：
   可以问"团队的技术栈是什么"、"实习期间会参与什么样的项目"
