1. FreeRTOS任务调度机制
================================================================================

问题：FreeRTOS的任务调度器是如何实现的？抢占式调度和协作式调度有什么区别？在OV_Watch项目中什么场景下需要用协作式调度？

答案：

FreeRTOS的调度器是核心，负责决定哪个任务获得CPU使用权。

【调度器实现原理】
- 调度器在系统启动时通过vTaskStartScheduler()函数启动
- 它基于任务就绪链表（Ready List）来选择下一个要运行的任务
- 每个任务有一个优先级，调度器总是选择最高优先级的就绪任务执行
- 当有更高优先级任务就绪时，会发生任务切换

【两种调度方式】

1）抢占式调度（Preemptive Scheduling）
- 高优先级任务可以强制剥夺低优先级任务的CPU使用权
- 适用于对实时性要求高的场景
- FreeRTOS默认使用这种方式
- 通过configUSE_PREEMPTION = 1 启用

2）协作式调度（Cooperative Scheduling）
- 任务必须主动放弃CPU，其他任务才能运行
- 通过configUSE_PREEMPTION = 0 启用
- 任务切换只发生在任务调用yield()或阻塞API时

【OV_Watch中的应用场景】
- 协作式调度适用于：需要严格顺序执行的操作、不希望被中断的关键数据处理
- 例如：传感器数据连续读取过程中不希望被其他任务打断
- 或者：GUI刷新时避免画面撕裂

2. 内存管理
================================================================================

问题：FreeRTOS的堆内存管理有哪几种算法（heap_1~heap_5）？OV_Watch项目选择的是哪种？解释其优缺点。

答案：

FreeRTOS提供了5种动态内存分配算法，位于heap_1.c到heap_5.c中：

【heap_1 - 简单固定块分配】
- 优点：执行速度快，代码量小，无内存碎片
- 缺点：不能释放内存，无法使用互斥量
- 适用：创建后不删除任务的简单系统

【heap_2 - 最佳匹配算法】
- 优点：可以释放内存，比heap_3节约内存
- 缺点：可能产生内存碎片
- 适用：需要动态创建/删除任务的系统

【heap_3 - 简单包装】
- 优点：使用标准malloc/free，线程安全
- 缺点：执行慢，占用空间大
- 适用：对性能要求不高的简单系统

【heap_4 - 首次匹配算法】
- 优点：可以释放内存，合并相邻空闲块
- 缺点：可能产生碎片
- 适用：需要频繁创建/删除任务的系统

【heap_5 - 最佳匹配+跨内存堆】
- 优点：可在多个非连续内存区域分配
- 缺点：最复杂
- 适用：需要在不同内存区域分配的系统

【OV_Watch项目推荐】
- 推荐使用heap_4，因为智能手表需要频繁创建/删除任务
- 配置方式：configUSE_HEAP_SCHEME = 4

3. 临界区保护
================================================================================

问题：在FreeRTOS中如何保护临界区？taskENTER_CRITICAL()和taskDISABLE_INTERRUPTS()的区别是什么？什么情况下必须用后者？

答案：

【临界区保护方法】

1）进入临界区的方法：
- taskENTER_CRITICAL() - 禁用系统中断
- taskDISABLE_INTERRUPTS() - 禁用所有中断
- uxTaskGetSystemState()期间自动保护

2）退出临界区：
- taskEXIT_CRITICAL()
- taskENABLE_INTERRUPTS()

【两者区别】

taskENTER_CRITICAL():
- 只禁用FreeRTOSConfig.h中配置的中断（通常是configMAX_SYSCALL_INTERRUPT_PRIORITY以下的中断）
- 允许更高优先级的中断嵌套
- 对系统影响较小
- 适用于大多数临界区保护场景

taskDISABLE_INTERRUPTS():
- 禁用所有中断，包括所有优先级
- 彻底关闭中断，无法嵌套
- 对系统影响大，可能导致实时性问题

【必须使用taskDISABLE_INTERRUPTS()的情况】
- 需要完全禁止中断以保证原子操作的绝对安全
- 与硬件直接交互的关键代码段
- 中断服务程序（ISR）中必须使用FromISR版本的API
- 需要访问正在被中断服务程序共享的数据时

4. LVGL渲染机制
================================================================================

问题：LVGL的脏区（Dirty Area）渲染原理是什么？如何优化OV_Watch这种小尺寸屏幕的渲染性能？

答案：

【脏区渲染原理】

LVGL的脏区机制通过以下步骤实现优化：

1）变化检测
- 当GUI对象属性改变时（如文本、颜色变化）
- LVGL标记该对象对应的区域为"脏"
- 使用位图或矩形区域记录需要重绘的位置

2）区域合并
- 多个小脏区可能合并成一个大区域
- 减少渲染调用次数，提高效率

3）分层渲染
- LVGL支持多层显示，每层独立渲染
- 脏区只影响相关层，其他层保持不变

4）按需绘制
- 显示驱动只需要绘制脏区内容
- 非脏区保持原有显示内容

【小尺寸屏幕优化策略】

1）减少对象数量
- 简化UI层次，避免过深的父子关系
- 尽量使用基础控件的组合而非自定义复杂控件

2）优化绘图属性
- 减少使用复杂的阴影、渐变效果
- 使用纯色填充代替图片背景

3）利用双缓冲
- 使用framebuffer避免闪烁
- 在内存中完成所有绘制后再一次性刷新屏幕

4）局部刷新
- 只更新变化的部分而非整个屏幕
- LVGL的 invalidated() 函数可以指定局部刷新区域

5）使用合适分辨率
- 根据屏幕实际分辨率设置LVGL
- 不必要的高分辨率会增加内存和渲染负担

5. 双缓冲技术
================================================================================

问题：解释双缓冲（Double Buffer）原理，在LVGL中如何实现？这对智能手表显示有什么帮助？

答案：

【双缓冲原理】

双缓冲是一种显示技术，使用两个缓冲区交替工作：

1）缓冲区结构
- 缓冲区A（后端缓冲）：CPU/MCU进行绘制
- 缓冲区B（前端缓冲）：显示控制器读取并显示

2）工作流程
- 帧N：CPU向缓冲区A写入下一帧数据，显示控制器读取缓冲区B显示
- 帧N+1：CPU向缓冲区B写入，显示控制器读取缓冲区A显示
- 两个缓冲区交替使用，周而复始

3）优势
- 避免屏幕闪烁（单缓冲在写入时可能显示部分更新的画面）
- 提高渲染效率（可以并行进行显示和绘制）
- 支持复杂动画效果

【LVGL中的实现方式】

1）配置LVGL使用双缓冲
- 在lv_conf.h中启用双缓冲：#define LV_COLOR_DEPTH 16
- 定义两个framebuffer缓冲区
- 调用lv_disp_flush()时在缓冲区间切换

2）实现示例
```c
// 定义两个缓冲区
static lv_color_t buf1[DISPLAY_WIDTH * DISPLAY_HEIGHT / 10];
static lv_color_t buf2[DISPLAY_WIDTH * DISPLAY_HEIGHT / 10];

// 初始化显示驱动
lv_disp_drv_t disp_drv;
lv_disp_drv_init(&disp_drv);
disp_drv.flush_cb = my_flush_cb;
disp_drv.buffer = &disp_buf;
lv_disp_drv_register(&disp_drv);

// flush回调函数实现双缓冲切换
void my_flush_cb(lv_disp_drv_t *drv, const lv_area_t *area, lv_color_t *color_p)
{
    // 将缓冲区数据传输到显示控制器
    // ...
    lv_disp_flush_ready(drv);  // 通知LVGL此缓冲区已用完
}
```

【对智能手表的帮助】

1）提升显示流畅度
- 手表界面需要流畅的动画效果
- 双缓冲确保动画无闪烁、无撕裂

2）降低功耗
- 减少重复绘制次数
- 可以在低刷新率模式下工作

3）优化内存使用
- 小尺寸屏幕（240x240或360x360）所需缓冲区不大
- 可以在有限RAM中实现双缓冲

6. I2C总线冲突
================================================================================

问题：当多个I2C设备挂载在同一总线上时，如何处理地址冲突问题？OV_Watch的光学传感器和陀螺仪通信有什么注意事项？

答案：

【I2C地址冲突处理】

1）I2C地址基础
- 标准I2C设备地址为7位（或10位扩展）
- 第8位表示读/写方向
- 实际通信时地址字节 = (设备地址 << 1) | R/W

2）常见I2C设备地址
- MAX30102（心率传感器）：0xAE（写）/0xAF（读）
- MPU6050（陀螺仪）：0xD0（写）/0xD1（读）
- BMP280（气压传感器）：0xEC（写）/0xED（读）
- ST7789（屏幕驱动）：0xFE（写）

3）地址冲突解决方案
- 更换不同地址的传感器型号
- 使用I2C开关（如PCA9548）扩展总线
- 软件模拟I2C时序，分时复用

【OV_Watch传感器注意事项】

1）MAX30102光学传感器
- I2C地址：0xAE（7位地址0x57）
- 需要注意：
  * 采样率配置（默认100Hz）
  * LED电流设置（避免灼伤皮肤）
  * 环境光干扰处理
  * FIFO数据读取要及时

2）MPU6050/ ICM20600 陀螺仪
- I2C地址：0xD0（7位地址0x68）
- 需要注意：
  * 初始化时可能需要等待自检完成
  * 配置合适的量程（±2000°/s陀螺仪，±16g加速度）
  * 使用FIFO批量读取数据减少I2C通信次数
  * 电源管理：进入低功耗模式

3）I2C总线使用注意事项
- 确保每个设备有独立的地址
- 注意上拉电阻选择（通常4.7KΩ）
- 降低I2C速率（400KHz以下）提高通信可靠性
- 添加错误处理和重试机制

7. 心率算法
================================================================================

问题：光学心率传感器的PPG信号是如何转换成心率值的？请解释运动伪影消除算法。

答案：

【PPG信号转心率值的原理】

1）PPG（光电容积脉搏波）基础
- 原理：血液对光的吸收随脉搏变化
- LED照射皮肤，光电二极管接收反射光
- 心脏跳动时血容量变化导致光强度变化

2）信号处理流程
```
光电传感器原始信号
    ↓
    ↓  （硬件：光电二极管 + I/V转换）
    ↓
模拟信号预处理（滤波、放大）
    ↓
ADC采样（通常100-400Hz采样率）
    ↓
    ↓  （软件：数字滤波）
    ↓
去基线漂移（高通滤波）
    ↓
带通滤波（0.5-4Hz，保留心率范围）
    ↓
    ↓
峰值检测（找波峰）
    ↓
计算峰-峰间隔（RR间期）
    ↓
    ↓  （根据RR间期计算心率）
    ↓
心率值（BPM）
```

3）心率计算方法
- 方法1：简单计数 - 一分钟内波峰数
- 方法2：即时计算 - 根据最近几个RR间期的平均值
- 公式：BPM = 60000 / 平均RR间期（毫秒）

【运动伪影消除算法】

1）运动伪影（Motion Artifact）问题
- 运动导致传感器与皮肤接触变化
- 产生大幅度的低频干扰信号
- 可能完全掩盖真实PPG信号

2）常见消除算法

a）自适应滤波
- 使用自适应滤波器（如LMS算法）
- 参考运动传感器（三轴加速度计）
- 从PPG信号中减去运动干扰分量

b）多位置采样
- 使用多个光电二极管不同位置
- 运动伪影对不同位置影响不同
- 通过信号融合提高准确性

c）信号质量评估
- 计算信号的信噪比（SNR）
- 低于阈值时放弃计算或提示用户
- 只在信号质量好时输出心率

d）时域/频域分析结合
- 时域：检测波峰波谷
- 频域：FFT分析频谱能量
- 两种方法互相验证

e）卡尔曼滤波
- 对心率值进行预测和校正
- 融合加速度计数据
- 适用于实时处理

3）MAX30102内置算法
- MAX30102芯片内置心率算法
- 提供FIFO数据直接读取
- 内部完成部分滤波处理

8. 低功耗设计
================================================================================

问题：STM32F411的功耗模式有哪些？在OV_Watch中如何设计息屏显示（Always-On Display）功能？

答案：

【STM32F411功耗模式】

1）运行模式（Run Mode）
- M4核心全速运行
- 所有外设可工作
- 功耗最高：约100mA

2）睡眠模式（Sleep Mode）
- CPU停止，外设继续运行
- 任一中断可唤醒
- 功耗约：20-30mA

3）停止模式（Stop Mode）
- 所有时钟停止
- SRAM和寄存器数据保留
- 任一外部中断可唤醒
- 功耗约：10-50μA

4）待机模式（Standby Mode）
- 几乎完全掉电
- 仅RTC和备份寄存器保留
- 仅特定唤醒引脚可唤醒
- 功耗约：2-5μA

【Always-On Display设计】

1）基本原理
- 部分屏幕区域持续显示时间等信息
- 其他区域关闭以省电
- 利用LVGL的图层功能实现

2）实现方案

a）分层显示设计
```c
// 息屏显示层（始终开启）
lv_obj_t *screen_always_on;
// 正常显示层（关闭时禁用）
lv_obj_t *screen_normal;

// 息屏时只刷新息屏层
void enter_aod_mode(void)
{
    lv_obj_add_flag(screen_normal, LV_OBJ_FLAG_HIDDEN);
    lv_obj_clear_flag(screen_always_on, LV_OBJ_FLAG_HIDDEN);
    // 设置低刷新率
    lv_disp_set_refresh_time(lv_disp_get_default(), 1000);  // 1秒刷新一次
}
```

b）部分屏幕刷新
- 息屏时只点亮必要的像素
- 黑色背景不点亮像素（OLED特性）
- LCD需要持续刷新但可以降低帧率

c）低功耗外设协同
- 关闭不必要的传感器
- 心率传感器在息屏时停止采样
- 陀螺仪进入低功耗模式

d）时间显示优化
- 使用简单的数字字体减少渲染量
- 预先渲染静态内容到framebuffer
- 只更新时间数字部分

3）功耗优化要点
- 选择合适的息屏刷新率（1Hz足够）
- 减少背景光（背光亮度调低）
- 利用RTC周期性唤醒更新显示
- 关闭未使用的外设时钟

9. 中断与实时性
================================================================================

问题：FreeRTOS的中断嵌套是如何实现的？中断服务程序（ISR）中能否调用FreeRTOS API？需要注意什么？

答案：

【FreeRTOS中断嵌套机制】

1）中断嵌套基础
- STM32支持中断优先级嵌套
- 高优先级中断可以打断低优先级中断
- FreeRTOS可以配置支持中断嵌套

2）配置要求
```c
// FreeRTOSConfig.h
#define configMAX_API_CALL_INTERRUPT_PRIORITY  5   // 允许在中断中调用的最高优先级
#define configKERNEL_INTERRUPT_PRIORITY         15 // 内核中断优先级（最低）
```

3）中断优先级分组
- STM32的NVIC使用4位优先级字段
- 可配置为：0位子优先级/4位抢占优先级 到 4位子优先级/0位抢占优先级
- FreeRTOS使用分组：2位抢占优先级 + 2位子优先级

【ISR中FreeRTOS API使用规则】

1）基本原则
- 不是所有API都可以在ISR中调用
- 必须使用FromISR版本的API
- 带FromISR后缀的函数才是中断安全的

2）可用API（FromISR版本）
- xQueueSendFromISR()
- xQueueReceiveFromISR()
- xSemaphoreGiveFromISR()
- xTaskNotifyFromISR()
- xEventGroupSetBitsFromISR()

3）禁止在ISR中调用的API
- 普通的xQueueSend()（会阻塞）
- 普通的xSemaphoreTake()（会阻塞）
- vTaskDelay()等任务级API

4）使用示例
```c
void UART_IRQHandler(void)
{
    BaseType_t xHigherPriorityTaskWoken = pdFALSE;

    if (USART_GetITStatus(USART1, USART_IT_RXNE) != RESET)
    {
        uint8_t data = USART_ReceiveData(USART1);
        // 使用FromISR版本
        xQueueSendFromISR(xUartQueue, &data, &xHigherPriorityTaskWoken);
    }

    // 强制上下文切换（如果需要）
    portYIELD_FROM_ISR(xHigherPriorityTaskWoken);
}
```

【注意事项】

1）中断优先级必须高于内核优先级
- configMAX_API_CALL_INTERRUPT_PRIORITY 定义了安全调用的上限
- 低于该值的中断可以安全调用FromISR API

2）资源保护
- ISR中不能使用互斥量（因为不可重入）
- 使用二进制信号量代替

3）快速执行
- ISR中代码应尽可能短
- 复杂处理放到任务中执行

4）临界区
- ISR中调用FromISR API会自动处理临界区
- 不需要额外调用taskENTER_CRITICAL()

10. SPI DMA传输
================================================================================

问题：解释SPI DMA传输的工作原理，为什么使用DMA可以提高数据传输效率？这对手表传感器数据读取有什么意义？

答案：

【SPI DMA传输原理】

1）传统SPI传输方式（轮询/POLLING）
- CPU逐字节发送/接收数据
- 每发送一个字节，CPU等待TXE标志
- 每接收一个字节，CPU读取DR寄存器
- CPU全程参与，效率低下

2）DMA传输方式
- DMA（Direct Memory Access）控制器直接在外设和内存间传输数据
- CPU只需配置一次传输参数
- DMA控制器自动完成数据传输
- 传输完成后产生中断通知CPU

3）DMA工作流程
```
配置阶段：
1. 设置DMA源地址（SPI_DR寄存器）
2. 设置DMA目标地址（内存缓冲区）
3. 设置传输数据长度
4. 启用DMA通道

传输阶段：
1. CPU执行其他任务
2. DMA控制器自动逐字节传输
3. 每完成一个数据项，DMA自动递增地址

完成阶段：
1. 传输完成触发DMA中断
2. CPU处理中断，读取数据
3. 可以使用信号量通知任务数据已就绪
```

【提高效率的原因】

1）CPU解放
- CPU无需等待每个字节的发送/接收
- 可以执行其他计算任务
- 提高整体系统并发性

2）减少中断次数
- 轮询方式：每个字节产生一次中断（或大量轮询）
- DMA方式：整个缓冲区传输完成才产生一次中断
- 显著减少中断开销

3）提高传输速度
- DMA传输速率可以达到更高
- 减少CPU等待时间
- 支持更高的SPI时钟频率

【对手表传感器数据读取的意义】

1）批量数据读取
- 陀螺仪/加速度计FIFO可以批量读取
- 心率传感器FIFO包含多组采样数据
- DMA一次性读取整个FIFO，减少通信时间

2）实时性保证
- 传感器数据采集不会占用过多CPU时间
- 留出更多时间给GUI和其他任务
- 保证系统响应性

3）降低功耗
- CPU更短时间处于活动状态
- 可以更快进入低功耗模式
- 对电池供电的智能手表很重要

4）实现示例
```c
// SPI DMA配置
void SPI1_DMA_Init(void)
{
    // 使能DMA时钟
    RCC_AHB1PeriphClockCmd(RCC_AHB1Periph_DMA2, ENABLE);

    // 配置DMA（以RX为例）
    DMA_InitTypeDef DMA_InitStructure;
    DMA_InitStructure.DMA_Channel = DMA_Channel_0;
    DMA_InitStructure.DMA_PeripheralBaseAddr = (uint32_t)&SPI1->DR;
    DMA_InitStructure.DMA_Memory0BaseAddr = (uint32_t)rx_buffer;
    DMA_InitStructure.DMA_DIR = DMA_DIR_PeripheralToMemory;
    DMA_InitStructure.DMA_BufferSize = BUFFER_SIZE;
    DMA_InitStructure.DMA_PeripheralInc = DMA_PeripheralInc_Disable;
    DMA_InitStructure.DMA_MemoryInc = DMA_MemoryInc_Enable;
    DMA_InitStructure.DMA_PeripheralDataSize = DMA_PeripheralDataSize_Byte;
    DMA_InitStructure.DMA_MemoryDataSize = DMA_MemoryDataSize_Byte;
    DMA_InitStructure.DMA_Mode = DMA_Mode_Normal;
    DMA_InitStructure.DMA_Priority = DMA_Priority_High;

    DMA_Init(DMA2_Stream0, &DMA_InitStructure);
    DMA_Cmd(DMA2_Stream0, ENABLE);
}
```

11. 文件系统
================================================================================

问题：如果要在手表上存储健康数据，你会选择什么文件系统？LittleFS和FatFS各有什么优劣？

答案：

【智能手表存储需求分析】

1）典型数据存储需求
- 健康数据记录（心率、步数、睡眠）
- 设置参数保存
- 表盘图片存储
- 日志记录

2）存储介质
- SPI Flash（常见型号：W25Qxx，8-256MB）
- 内部Flash（STM32F411有512KB）

【LittleFS文件系统】

1）特点
- 专为嵌入式系统设计的日志型文件系统
- 掉电安全（power-loss resilience）
- 磨损均衡（wear leveling）内置
- 目录结构简单

2）优点
- 掉电安全：写入时先记录操作日志，系统崩溃可恢复
- 小体积：代码量小，约4KB
- 简单易用：API设计简洁
- 适合小容量存储设备
- 支持断电恢复

3）缺点
- 不支持目录层级（flat structure）
- 不适合大容量存储
- 不适合需要随机写入的场景

【FatFS文件系统】

1）特点
- 通用文件系统（Windows兼容）
- 支持长文件名
- 支持目录结构
- 多种配置选项

2）优点
- 广泛兼容：可被Windows/Linux/macOS识别
- 功能完整：支持目录、文件属性等
- 文档丰富：资料多，学习成本低
- 适合大容量存储
- 适合需要PC交互的场景

3）缺点
- 掉电不安全（容易丢失数据）
- 需要额外Flash空间做Wear leveling
- 代码量较大（约15-20KB）
- 对嵌入式不够"友好"

【选择建议】

【推荐OV_Watch项目使用LittleFS】
- 数据量不大（健康数据为主）
- 掉电安全很重要
- 代码空间有限
- 可靠性要求高

【使用FatFS的情况】
- 需要通过USB与电脑交换数据
- 存储大量媒体文件
- 已有成熟的Wear leveling方案

12. RTOS任务间通信
================================================================================

问题：FreeRTOS中队列（Queue）和消息缓冲区（Message Buffer）有什么区别？什么场景下选择哪种方式？

答案：

【队列（Queue）】

1）特点
- 队列可以存储多个数据项
- 先进先出（FIFO）顺序
- 数据复制到队列中（拷贝）
- 支持阻塞读取

2）关键API
```c
// 创建队列
QueueHandle_t xQueue = xQueueCreate(10, sizeof(uint32_t)); // 10个元素的32位队列

// 发送数据（阻塞）
xQueueSend(xQueue, &data, portMAX_DELAY);

// 接收数据
uint32_t received;
xQueueReceive(xQueue, &received, portMAX_DELAY);

// FromISR版本
xQueueSendFromISR(xQueue, &data, &xHigherPriorityTaskWoken);
```

3）适用场景
- 多生产者多消费者
- 需要数据排队处理
- 需要阻塞等待数据

【消息缓冲区（Message Buffer）】

1）特点
- 流式缓冲区（Stream Buffer）
- 字节流形式，顺序读取
- 数据复制到缓冲区
- 支持单读者单写者

2）关键API
```c
// 创建消息缓冲区
MessageBufferHandle_t xMessageBuffer = xMessageBufferCreate(1024); // 1KB缓冲区

// 发送数据
xMessageBufferSend(xMessageBuffer, data, strlen(data), 0);

// 接收数据
xMessageBufferReceive(xMessageBuffer, buffer, sizeof(buffer), portMAX_DELAY);
```

3）适用场景
- 连续数据流（如传感器数据）
- 简单的单对单通信
- 内存效率优先

【Streams Buffer vs Message Buffer】

1）Stream Buffer（流缓冲区）
- 单生产者-单消费者
- 轻量级，效率高
- 不保留消息边界

2）Message Buffer（消息缓冲区）
- 单生产者-单消费者
- 保留消息边界
- 支持变长消息

【选择指南】

【使用队列的情况】
- 多个任务需要通信
- 需要阻塞行为
- 数据项是结构体或复杂类型
- 需要FIFO顺序处理

【使用消息缓冲区的情况】
- 简单的点对点通信
- 传输连续的字节流
- 追求最小内存开销
- 不需要阻塞（轮询方式）

【OV_Watch项目推荐】
- 按键事件：队列（带阻塞）
- 传感器数据：消息缓冲区
- GUI更新通知：队列

13. GUI事件处理
================================================================================

问题：LVGL的事件驱动机制是如何工作的？点击、滑动、长按事件是如何区分和处理的？

答案：

【LVGL事件系统架构】

1）事件驱动模型
- LVGL是事件驱动的GUI库
- 用户交互产生事件（点击、滑动等）
- 事件分发到相应的对象
- 回调函数处理事件

2）事件类型
- LV_EVENT_PRESSED：按下
- LV_EVENT_RELEASED：释放
- LV_EVENT_CLICKED：点击（按下后释放）
- LV_EVENT_LONG_PRESSED：长按
- LV_EVENT_LONG_PRESSED_REPEAT：长按重复
- LV_EVENT_DRAG_BEGIN/END：拖动
- LV_EVENT_SCROLL：滚动
- LV_EVENT_VALUE_CHANGED：值改变

【事件处理机制】

1）事件绑定
```c
// 绑定事件回调

// 回调函数实现

{
    lv_event_code_t code = lv_event_get_code(e);
    lv_obj_t *obj = lv_event_get_target(e);

    if (code == LV_EVENT_CLICKED)
    {
        // 处理点击事件
        LV_LOG_USER("Button clicked!");
    }
}
```

2）事件传播
- 事件从子对象传播到父对象
- 可以使用lv_obj_set_parent()改变父子关系
- 可以在回调中阻止传播：lv_obj_stop_stopPropagation(e)

【点击、滑动、长按区分】

1）点击（Click）
- 条件：按下后短时间内释放
- 默认时间阈值：300ms（可配置）
- 触发事件：LV_EVENT_CLICKED

2）长按（Long Press）
- 条件：按下持续超过阈值时间
- 默认阈值：400ms（可配置）
- 触发事件：LV_EVENT_LONG_PRESSED
- 如果继续按住：触发LV_EVENT_LONG_PRESSED_REPEAT

3）滑动（Swipe/Drag）
- 条件：按下后移动一定距离
- 默认阈值：10px（可配置）
- 触发事件：LV_EVENT_DRAG_BEGIN、LV_EVENT_DRAG_END
- 滑动过程中：LV_EVENT_PRESSING

14. RTC校准
================================================================================

问题：智能手表的RTC如何保持准确？STM32的RTC精度受哪些因素影响？如何补偿？

答案：

【RTC精度影响因素】

1）晶振精度
- RTC通常使用32.768KHz晶振
- 常见误差：±10ppm到±50ppm
- 每天误差：0.86秒到4.3秒

2）温度漂移
- 晶振频率随温度变化（AT切晶体特性）
- 室温（25℃）精度最高
- 极端温度下误差增大

3）负载电容
- 匹配不当会导致频率偏差
- 需要根据晶振规格选择合适电容

4）供电影响
- RTC电源不稳定会导致计时误差
- VBAT供电切换时可能产生瞬态误差

【保持准确的方法】

1）选择高精度晶振
- 选用温度补偿晶振（TCXO）
- 或使用内置温度补偿的RTC芯片

2）硬件补偿
- 外部32.768KHz高精度晶振
- 匹配正确的负载电容
- 稳定的RTC电源（VBAT）

3）软件校准
- 通过网络时间协议（NTP）同步
- GPS时间同步
- 手动校准

【STM32 RTC软件校准】

1）使用校准寄存器
```c
// STM32F4 RTC校准
void RTC_Calibration(void)
{
    // 计算校准值
    // 假设每日误差+5秒
    // 校准值 = (误差秒数 / (86400 * 30)) * 2^20
    // = (5 / 2592000) * 1048576 ≈ 2

    RTC_InitTypeDef RTC_InitStruct;
    RTC_InitStruct.RTC_CalibSign = RTC_CalibSign_Positive;  // 正校准
    RTC_InitStruct.RTC_CalibValue = 2;  // 校准值

    RTC_RTCConfig(RTC_InitStruct);
}
```

2）手动时间同步
```c
// 与外部时间源同步
void sync_time_from_ntp(void)
{
    // 获取NTP时间
    uint32_t ntp_time = get_ntp_time();

    // 设置RTC时间
    RTC_TimeTypeDef RTC_TimeStruct;
    RTC_TimeStruct.RTC_Hours = (ntp_time >> 16) & 0xFF;
    RTC_TimeStruct.RTC_Minutes = (ntp_time >> 8) & 0xFF;
    RTC_TimeStruct.RTC_Seconds = ntp_time & 0xFF;

    RTC_SetTime(RTC_Format_BIN, &RTC_TimeStruct);
}
```

3）周期性校准
```c
// 每天自动校准一次
void daily_rtc_calibration(void)
{
    static uint32_t last_sync_time = 0;
    uint32_t current_time = get_unix_timestamp();

    // 每天同步一次（86400秒）
    if (current_time - last_sync_time >= 86400)
    {
        // 连接到手机获取准确时间
        if (ble_connected())
        {
            sync_time_from_phone();
            last_sync_time = current_time;
        }
    }
}
```

【智能手表特定考虑】

1）备用电源
- 使用VBAT引脚连接超级电容或电池
- 主电源断开时RTC继续运行

2）低功耗运行
- RTC在停止模式下继续工作
- 支持定时唤醒

3）夏令时处理
- 软件实现夏令时切换
- 存储时区信息

15. 电磁兼容设计
================================================================================

问题：智能手表PCB布局布线有哪些注意事项？模拟地和数字地如何处理？

答案：

【PCB布局原则】

1）分区规划
- 数字区：MCU、Flash、蓝牙芯片
- 模拟区：传感器模拟前端、ADC电路
- 电源区：LDO、充电管理、电池接口
- RF区：蓝牙天线、射频走线

2）分区隔离
- 各功能区用接地隔离带分开
- 避免数字信号干扰模拟电路
- 模拟信号走线远离数字信号

3）关键走线优先级
- 高速信号（SPI、I2S）：短而直，等长
- 模拟信号：远离干扰源
- 电源线：足够宽，降低压降
- 时钟线：远离I/O，用地线包围

【地线处理】

1）单点接地 vs 多点接地

a）单点接地
- 所有地连接到一个点
- 适用于低频电路（<1MHz）
- 优点：避免地环路
- 缺点：走线可能较长

b）多点接地
- 每个模块就近接地
- 适用于高频电路（>10MHz）
- 优点：降低接地阻抗
- 缺点：可能产生地环路

c）混合方式
- 智能手表采用混合接地
- 模拟部分单点接地
- 数字部分多点接地
- 两者在电源入口处连接

2）模拟地数字地连接

a）方法一：磁珠连接
- 阻隔高频噪声
- 低频信号可以通过
- 常用磁珠：100Ω @ 100MHz

b）方法二：0Ω电阻连接
- 简单可靠
- 直流和低频导通
- 成本低

c）方法三：直接连接
- 如果数字地很干净
- 可以直接连接
- 需要确保数字电路噪声不干扰模拟

【智能手表特定考虑】

1）天线设计
- 蓝牙天线净空区（Clearance）
- 天线下方禁止走线
- 使用接地保护环

2）电源完整性
- 去耦电容靠近芯片电源引脚
- 多层板使用电源层
- 大电流路径足够宽

3）ESD保护
- USB/充电接口加TVS管
- 按键接口加保护二极管
- 连接器处增加防护

4）走线宽度计算
- 1mm宽度约承载1A电流（1oz铜）
- 电源线根据电流计算宽度
- 信号线通常0.2-0.3mm

16. GPIO配置
================================================================================

问题：STM32的GPIO有哪几种模式？推挽输出和开漏输出的区别是什么？什么时候用开漏输出？

答案：

【GPIO模式（8种）】

输入模式：
1）浮空输入（Input Floating）
- 不连接内部上拉/下拉电阻
- 阻抗高，易受干扰
- 用于按钮/开关检测

2）上拉输入（Input Pull-Up）
- 内部连接VCC通过电阻
- 默认高电平
- 用于按钮/编码器

3）下拉输入（Input Pull-Down）
- 内部连接GND通过电阻
- 默认低电平
- 用于特定协议

输出模式：
4）推挽输出（Push-Pull Output）
- 输出高电平和低电平
- 驱动能力强
- 最常用

5）开漏输出（Open-Drain Output）
- 只能输出低电平/高阻态
- 需要外部上拉电阻
- I2C使用此模式

6）推挽复用功能（Alternate Function Push-Pull）
- 用于UART、SPI等外设
- 具备推挽特性

7）开漏复用功能（Alternate Function Open-Drain）
- 用于I2C等需要线与的协议
- 具备开漏特性

模拟模式：
8）模拟模式（Analog Mode）
- 用于ADC/DAC
- 禁用数字输入输出

【推挽 vs 开漏】

推挽输出：
```
高电平：PMOS导通，NMOS关闭，输出VCC
低电平：PMOS关闭，NMOS导通，输出GND
```
- 可以输出高低电平
- 驱动能力强
- 不能并联使用

开漏输出：
```
低电平：NMOS导通，输出GND
高阻态：NMOS关闭，输出由上拉电阻决定
```
- 只能输出低电平
- 需要外部上拉电阻
- 可以实现"线与"功能

【开漏使用场景】

1）I2C通信
- I2C需要线与（多个设备共享总线）
- 任何设备都可以拉低总线
- 需要上拉电阻将总线拉到高电平

2）电平转换
- 不同电压系统连接
- 开漏配合不同电压上拉

3）驱动LED
- 共阳极LED驱动
- 可以控制多颗LED

4）开中断检测
- 多个中断源"线与"到一根中断线

17. UART通信
================================================================================

问题：UART的波特率是怎么计算的？如果要115200波特率，配置USART初始化需要设置哪些参数？

答案：

【UART波特率计算】

1）基本公式
- 波特率 = USART时钟 / (16 × 分频系数)
- 分频系数 = USARTDIV
- USARTDIV = USART时钟 / (16 × 波特率)

2）STM32F4计算示例
- 系统时钟：84MHz（APB1为42MHz，APB2为84MHz）
- 目标波特率：115200

USARTDIV = 84000000 / (16 × 115200) ≈ 45.5729

- 整数部分：45 = 0x2D
- 小数部分：0.5729 × 16 = 9.17 ≈ 9

最终配置值：0x2D9

3）计算注意事项
- 波特率误差不超过 ±2.5%
- 115200实际：84000000/(16×45.5729) = 115198（误差0.002%）

【USART初始化参数】

```c
typedef struct
{
    uint32_t USART_BaudRate;        // 波特率：115200
    uint32_t USART_WordLength;      // 数据位：8位或9位
    uint32_t USART_StopBits;        // 停止位：0.5/1/1.5/2位
    uint32_t USART_Parity;          // 校验位：无/奇/偶
    uint32_t USART_Mode;            // 模式：TX/RX/全双工
    uint32_t USART_HardwareFlowControl; // 硬件流控制
} USART_InitTypeDef;
```

【配置示例】

```c
void UART_Init(void)
{
    USART_InitTypeDef USART_InitStruct;

    // 1. 使能USART时钟
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_USART1, ENABLE);

    // 2. 配置GPIO（PA9=TX, PA10=RX）
    GPIO_InitTypeDef GPIO_InitStruct;
    GPIO_InitStruct.GPIO_Pin = GPIO_Pin_9;
    GPIO_InitStruct.GPIO_Mode = GPIO_Mode_AF;
    GPIO_InitStruct.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_InitStruct.GPIO_OType = GPIO_OType_PP;
    GPIO_Init(GPIOA, &GPIO_InitStruct);

    // 3. 配置USART参数
    USART_InitStruct.USART_BaudRate = 115200;
    USART_InitStruct.USART_WordLength = USART_WordLength_8b;
    USART_InitStruct.USART_StopBits = USART_StopBits_1;
    USART_InitStruct.USART_Parity = USART_Parity_No;
    USART_InitStruct.USART_Mode = USART_Mode_Rx | USART_Mode_Tx;
    USART_InitStruct.USART_HardwareFlowControl = USART_HardwareFlowControl_None;

    USART_Init(USART1, &USART_InitStruct);

    // 4. 使能USART
    USART_Cmd(USART1, ENABLE);
}
```

18. FreeRTOS任务创建
================================================================================

问题：xTaskCreate()函数的参数分别代表什么？如何设置任务栈大小？

答案：

【xTaskCreate()函数原型】

```c
BaseType_t xTaskCreate(
    TaskFunction_t pvTaskCode,      // 任务函数指针
    const char * const pcName,      // 任务名称（字符串）
    const uint32_t ulStackDepth,    // 栈深度（字数，不是字节！）
    void *pvParameters,            // 传递给任务的参数
    UBaseType_t uxPriority,        // 任务优先级
    TaskHandle_t *pxCreatedTask   // 任务句柄（输出）
);
```

【参数详解】

1）pvTaskCode（任务函数）
- 任务入口函数
- 返回void，接受void*参数
- 必须是无限循环（while(1)）或调用vTaskDelete(NULL)
```c
void vTaskFunction(void *pvParameters)
{
    while(1)
    {
        // 任务代码
        vTaskDelay(pdMS_TO_TICKS(100));
    }
}
```

2）pcName（任务名）
- 用于调试和识别
- 最大configMAX_TASK_NAME_LEN字符
- 不用于任务间区分

3）ulStackDepth（栈深度）
- 重要：单位是**字数（Word）**，不是字节！
- STM32是32位，1字=4字节
- 例如：栈深度1000 = 4000字节实际栈空间

4）pvParameters（参数）
- 传递给任务的void*参数
- 可以传递结构体指针
- 在任务函数中通过pvParameters接收

5）uxPriority（优先级）
- 数值越小优先级越低（可配置）
- 范围：0到configMAX_PRIORITIES-1
- 通常从1开始（0为IDLE任务保留）

6）pxCreatedTask（句柄）
- 输出参数，用于后续操作
- 可用于删除、挂起、恢复任务
- 不需要可传NULL

【栈大小设置】

1）默认建议
- 简单任务：128-256字（512-1024字节）
- 复杂任务：512-1024字（2-4KB）
- GUI任务：1024+字（4KB+）

2）栈溢出检测
- 启用栈溢出检测：configCHECK_FOR_STACK_OVERFLOW = 1或2
- 任务切换时检查栈使用情况
- 溢出时调用钩子函数

3）计算方法
```c
// 估算栈使用
// 本地变量 + 函数调用栈 + 中断使用

// 例如：
void my_task(void *p)
{
    uint8_t buffer[100];  // 100字（32位） = 400字节
    some_function();      // 调用深度 × 本地变量

    // 加上中断栈余量
    // 建议预留50%
}
```

4）最佳实践
- 使用uxTaskGetStackHighWaterMark()监测
- 逐步调整到合适大小
- 宁可稍大不要溢出

19. 任务优先级
================================================================================

问题：FreeRTOS中任务优先级是如何映射的？数字越大优先级越高还是越低？

答案：

【FreeRTOS优先级规则】

1）优先级数值与优先级
- 数值越小，优先级越低
- 数值越大，优先级越高
- 0优先级最低（通常留给IDLE任务）

2）优先级配置
```c
// FreeRTOSConfig.h
#define configMAX_PRIORITIES    5   // 最大优先级数
#define configUSE_TIME_SLICING   1   // 启用时间片轮转
```

3）优先级设置
```c
// 创建任务时设置优先级
xTaskCreate(task_function, "Task", 256, NULL, 3, NULL);
// 优先级3，高于1和2

// 运行时修改
vTaskPrioritySet(task_handle, 4);

// 获取优先级
UBaseType_t priority = uxTaskPriorityGet(task_handle);
```

【优先级反转问题】

1）问题描述
- 高优先级任务等待低优先级任务释放资源
- 中优先级任务抢占低优先级任务
- 导致高优先级任务反而被延迟

2）解决方案：优先级继承
- 临时提升低优先级任务到高优先级
- FreeRTOS互斥量支持此功能

```c
// 使用互斥量避免优先级反转
SemaphoreHandle_t xMutex = xSemaphoreCreateMutex();

void high_priority_task(void *p)
{
    xSemaphoreTake(xMutex, portMAX_DELAY);
    // 临界资源
    xSemaphoreGive(xMutex);
}
```

【OV_Watch项目推荐优先级分配】

| 优先级 | 任务 | 说明 |
|--------|------|------|
| 5 | GUI刷新任务 | 实时显示 |
| 4 | 传感器读取任务 | 高频率 |
| 3 | 通信任务 | BLE/UART |
| 2 | 数据处理任务 | 算法处理 |
| 1 | 记录任务 | 存储数据 |
| 0 | IDLE任务 | 最低优先级 |

20. 队列操作
================================================================================

问题：xQueueSend()和xQueueReceive()是阻塞还是非阻塞的？如何实现超时等待？

答案：

【队列操作模式】

1）阻塞模式
- 参数xTicksToWait > 0 或 portMAX_DELAY
- 队列满时发送阻塞，队列空时接收阻塞
- 等待期间CPU可执行其他任务

2）非阻塞模式
- 参数xTicksToWait = 0
- 队列满/空时立即返回
- 不阻塞，立即返回错误

【API详解】

1）发送函数
```c
BaseType_t xQueueSend(
    QueueHandle_t xQueue,              // 队列句柄
    const void *pvItemToQueue,         // 数据指针
    TickType_t xTicksToWait            // 阻塞时间
);
// 返回：pdTRUE成功，errQUEUE_FULL失败

// 阻塞1秒
xQueueSend(xQueue, &data, pdMS_TO_TICKS(1000));

// 阻塞无限
xQueueSend(xQueue, &data, portMAX_DELAY);

// 非阻塞
xQueueSend(xQueue, &data, 0);
```

2）接收函数
```c
BaseType_t xQueueReceive(
    QueueHandle_t xQueue,             // 队列句柄
    void *pvBuffer,                    // 接收缓冲区
    TickType_t xTicksToWait           // 阻塞时间
);
// 返回：pdTRUE成功，errQUEUE_EMPTY失败
```

【超时时间计算】

```c
// pdMS_TO_TICKS 转换毫秒到系统节拍
TickType_t xTicksToWait = pdMS_TO_TICKS(500);  // 500ms

// 常见用法
if (xQueueReceive(xQueue, &data, pdMS_TO_TICKS(100)) == pdTRUE)
{
    // 收到数据
}
else
{
    // 超时
}
```

【阻塞超时类型】

1）相对超时
- 从调用时开始计算的固定时间
- pdMS_TO_TICKS() 使用相对超时

2）绝对超时
- 指定具体的系统时间点
- 较少使用

【中断中使用】

中断中必须使用FromISR版本：

```c
BaseType_t xQueueSendFromISR(
    QueueHandle_t xQueue,
    const void *pvItemToQueue,
    BaseType_t *pxHigherPriorityTaskWoken
);

BaseType_t xQueueReceiveFromISR(
    QueueHandle_t xQueue,
    void *pvBuffer,
    BaseType_t *pxHigherPriorityTaskWoken
);
```

23. I2C通信
================================================================================

问题：I2C的起始位、停止位、ACK/NACK是如何产生的？主机如何判断从机是否响应？

答案：

【I2C时序基础】

1）起始位（Start Condition）
- SCL高电平时，SDA从高变低
- 表示开始传输
- 所有从机监听总线

2）停止位（Stop Condition）
- SCL高电平时，SDA从低变高
- 表示传输结束
- 释放总线

3）ACK/NACK
- 第9个时钟脉冲时
- 发送方释放SDA
- 接收方拉低SDA为ACK，保持高为NACK

【主机产生信号】

1）起始位产生（软件模拟）
```c
void I2C_Start(void)
{
    SDA_OUTPUT;    // SDA设为输出
    SCL_OUTPUT;

    SDA_HIGH;     // 确保SDA高
    SCL_HIGH;     // 确保SCL高
    delay_us(5);

    SDA_LOW;      // SDA变低，产生起始位
    delay_us(5);

    SCL_LOW;      // 准备开始传输
}
```

2）发送字节+ACK
```c
void I2C_SendByte(uint8_t data)
{
    SDA_OUTPUT;

    for (int i = 0; i < 8; i++)
    {
        if (data & 0x80)
            SDA_HIGH;
        else
            SDA_LOW;

        SCL_HIGH;
        delay_us(5);
        SCL_LOW;
        data <<= 1;
    }

    // ACK周期
    SDA_INPUT;    // 释放SDA
    SCL_HIGH;
    delay_us(5);

    // 检查ACK（软件读取）
    // ACK = 0，从机响应
    // ACK = 1，从机未响应

    SCL_LOW;
}
```

3）停止位产生
```c
void I2C_Stop(void)
{
    SDA_OUTPUT;
    SDA_LOW;

    SCL_HIGH;
    delay_us(5);

    SDA_HIGH;     // SDA变高，产生停止位
    delay_us(5);
}
```

【判断从机响应】

```c
bool I2C_WaitAck(void)
{
    uint8_t ack;

    SDA_INPUT;
    SCL_HIGH;
    delay_us(5);

    ack = SDA_READ;  // 读取SDA状态
    SCL_LOW;

    return (ack == 0);  // 0=ACK, 1=NACK
}

// 完整写操作示例
bool I2C_WriteReg(uint8_t addr, uint8_t reg, uint8_t data)
{
    I2C_Start();

    // 发送设备地址（写）
    I2C_SendByte(addr << 1);  // 写位为0
    if (!I2C_WaitAck()) { I2C_Stop(); return false; }

    // 发送寄存器地址
    I2C_SendByte(reg);
    if (!I2C_WaitAck()) { I2C_Stop(); return false; }

    // 发送数据
    I2C_SendByte(data);
    if (!I2C_WaitAck()) { I2C_Stop(); return false; }

    I2C_Stop();
    return true;
}
```

24. SPI通信
================================================================================

问题：SPI的四种模式（Mode 0~3）有什么区别？如何根据从设备选择正确的模式？

答案：

【SPI四种模式】

SPI模式由CPOL和CPHA两个参数决定：

1）CPOL（Clock Polarity）- 时钟极性
- CPOL=0：空闲时SCK为低电平
- CPOL=1：空闲时SCK为高电平

2）CPHA（Clock Phase）- 时钟相位
- CPHA=0：第一个边沿采样
- CPHA=1：第二个边沿采样

【模式对照表】

| 模式 | CPOL | CPHA | 空闲SCK | 采样边沿 |
|------|------|------|---------|---------|
| Mode 0 | 0 | 0 | 低 | 第一个边沿（上升） |
| Mode 1 | 0 | 1 | 低 | 第二个边沿（下降） |
| Mode 2 | 1 | 0 | 高 | 第一个边沿（下降） |
| Mode 3 | 1 | 1 | 高 | 第二个边沿（上升） |

【时序图】

```
Mode 0 (CPOL=0, CPHA=0):
     _   _   _   _   _   _   _   _
SCK  |_| |_| |_| |_| |_| |_| |_| |_
        _       _       _       _
SDA   |___|___|   |___|___|   |___
        ^       ^       ^       ^
      采样    采样    采样    采样

Mode 3 (CPOL=1, CPHA=1):
       _   _   _   _   _   _   _   _
SCK   |_| |_| |_| |_| |_| |_| |_| |_
     _       _       _       _
SDA  |___|___|   |___|___|   |___
           ^       ^       ^       ^
         采样    采样    采样    采样
```

【常见设备的SPI模式】

| 设备 | 模式 | 说明 |
|------|------|------|
| ST7789屏幕 | Mode 0 或 Mode 3 | 通常Mode 0 |
| W25Q Flash | Mode 0 | 常见 |
| MAX31855热电偶 | Mode 1 | 常见 |
| NRF24L01+ | Mode 0 | 常见 |
| SD卡 | Mode 0 | SPI模式默认 |

【STM32配置】

```c

{

    SPI_InitStruct.SPI_Mode = SPI_Mode_Master;
```

25. PWM输出
================================================================================

问题：如何使用STM32的定时器输出PWM？在心率传感器中PWM用于什么功能？

答案：

【STM32定时器PWM配置】

1）PWM原理
- 定时器产生周期性的计数
- CCR寄存器控制比较值
- 输出引脚根据比较结果翻转
- 产生占空比可调的方波

```c
void TIM_PWM_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStruct;
    TIM_TimeBaseInitTypeDef TIM_InitStruct;
    TIM_OCInitTypeDef TIM_OCInitStruct;

    // 1. 使能时钟
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM3, ENABLE);
    RCC_AHB1PeriphClockCmd(RCC_AHB1Periph_GPIOB, ENABLE);

    // 2. 配置GPIO（PB0为TIM3 CH3）
    GPIO_InitStruct.GPIO_Pin = GPIO_Pin_0;
    GPIO_InitStruct.GPIO_Mode = GPIO_Mode_AF;
    GPIO_InitStruct.GPIO_Speed = GPIO_Speed_100MHz;
    GPIO_InitStruct.GPIO_OType = GPIO_OType_PP;
    GPIO_InitStruct.GPIO_PuPd = GPIO_PuPd_NOPULL;
    GPIO_Init(GPIOB, &GPIO_InitStruct);

    GPIO_PinAFConfig(GPIOB, GPIO_PinSource0, GPIO_AF_TIM3);

    // 3. 配置定时器
    TIM_InitStruct.TIM_Prescaler = 84 - 1;         // 84MHz/84 = 1MHz
    TIM_InitStruct.TIM_CounterMode = TIM_CounterMode_Up;
    TIM_InitStruct.TIM_Period = 1000 - 1;         // 1MHz/1000 = 1kHz PWM
    TIM_InitStruct.TIM_ClockDivision = TIM_CKD_DIV1;
    TIM_TimeBaseInit(TIM3, &TIM_InitStruct);

    // 4. 配置PWM输出
    TIM_OCInitStruct.TIM_OCMode = TIM_OCMode_PWM1;
    TIM_OCInitStruct.TIM_OutputState = TIM_OutputState_Enable;
    TIM_OCInitStruct.TIM_Pulse = 500;              // 50%占空比
    TIM_OCInitStruct.TIM_OCPolarity = TIM_OCPolarity_High;

    TIM_OC3Init(TIM3, &TIM_OCInitStruct);
    TIM_OC3PreloadConfig(TIM3, TIM_OCPreload_Enable);

    TIM_ARRPreloadConfig(TIM3, ENABLE);

    // 5. 使能定时器
    TIM_Cmd(TIM3, ENABLE);
}

// 动态改变占空比
void Set_PWM_Duty(uint32_t duty)
{
    // duty: 0-1000
    TIM_SetCompare3(TIM3, duty);
}
```

【心率传感器中的PWM】

1）典型心率传感器模块（如Pulse Sensor）
- 内置绿色LED通过PWM控制亮度
- PWM频率：约500Hz-1kHz
- 通过调节占空比控制LED电流

2）MAX30102的PWM用途
- 实际上I2C控制，不是传统PWM
- 但有PWM型号版本用于调试输出
- 内部使用时间戳采样FIFO数据

3）其他用途

26. ADC采集
================================================================================

问题：STM32的ADC有哪些采样模式（单次、连续、扫描）？如何配置多通道采集？

答案：

【ADC工作模式】

1）单次转换模式
- 转换一个通道后停止
- 需要软件触发或定时器触发
- 适用于单通道采样

2）连续转换模式
- 一个通道连续转换
- 适用于单通道高速采样

3）扫描模式
- 多个通道按顺序转换
- 配合DMA使用
- 适用于多通道采样

4）间断模式
- 每组转换指定数量通道
- 需要多次触发

【多通道DMA配置】

```c
void ADC_MultiChannel_Init(void)

    ADC_Init(ADC1, &ADC_InitStruct);
```

27. 看门狗
================================================================================

问题：STM32的独立看门狗（IWDG）和窗口看门狗（WWDG）有什么区别？什么情况下需要使用？

答案：

【两种看门狗对比】

| 特性 | 独立看门狗（IWDG） | 窗口看门狗（WWDG） |
|------|-------------------|-------------------|
| 时钟源 | LSI（40KHz） | APB1（36MHz） |
| 精度 | 低（慢） | 高（快） |
| 用途 | 死机/程序跑飞 | 程序异常逻辑 |
| 窗口功能 | 无 | 有 |
| 低功耗 | 可在停止/待机模式工作 | 只能在运行/睡眠模式 |

【独立看门狗】

```c
void IWDG_Init(void)
{
    // 1. 启动IWDG（写入0x5555允许访问）
    IWDG_WriteAccessCmd(IWDG_WriteAccess_Enable);

    // 2. 设置预分频（40KHz/256 = 156Hz）
    IWDG_SetPrescaler(IWDG_Prescaler_256);

    // 3. 设置重装载值（156Hz * 1s = 156）
    IWDG_SetReload(156);

    // 4. 装载值并启动
    IWDG_ReloadCounter();
    IWDG_Enable();
}

// 喂狗
void Feed_IWDG(void)
{
    IWDG_ReloadCounter();
}
```

【窗口看门狗】

```c
void WWDG_Init(void)
{
    // 1. 开启WWDG时钟
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_WWDG, ENABLE);

    // 2. 配置WWDG
    // 时钟 = 36MHz / 4096 / 8 = 1098Hz
    // 超时 = 1098 / (127-80+1) ≈ 23ms
    WWDG_SetPrescaler(WWDG_Prescaler_8);
    WWDG_SetWindowValue(80);     // 窗口上限
    WWDG_Enable(127);            // 计数器上限，启动WWDG
}

// 喂狗（必须在窗口时间内）
void Feed_WWDG(void)
{
    WWDG_SetCounter(100);        // 在窗口内重置计数器
}
```

【使用场景选择】

【使用IWDG】
- 主程序死循环
- 看门狗失效时
- 需要在低功耗模式下运行
- 简单的超时检测
- OV_Watch推荐使用

【使用WWDG】
- 程序执行逻辑错误
- 必须在特定时间窗口内喂狗
- 需要更快的检测速度
- 应用程序级别的监控

28. NVIC中断优先级
================================================================================

问题：STM32的NVIC中，优先级分组是什么？如何计算抢占优先级和子优先级？

答案：

【优先级分组】

STM32使用4位优先级字段，通过分组决定抢占和子优先级数量：

| 分组 | 抢占优先级位数 | 子优先级位数 | 抢占优先级范围 | 子优先级范围 |
|------|--------------|-------------|--------------|-------------|
| 0 | 0 | 4 | 0 | 0-15 |
| 1 | 1 | 3 | 0-1 | 0-7 |
| 2 | 2 | 2 | 0-3 | 0-3 |
| 3 | 3 | 1 | 0-7 | 0-1 |
| 4 | 4 | 0 | 0-15 | 无 |

【分组配置】

```c
void NVIC_Config(void)
{
    NVIC_InitTypeDef NVIC_InitStruct;

    // 设置优先级分组（抢占2位，子2位）
    NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);

    // 配置中断
    NVIC_InitStruct.NVIC_IRQChannel = USART1_IRQn;
    NVIC_InitStruct.NVIC_IRQChannelPreemptionPriority = 2;  // 抢占优先级 0-3
    NVIC_InitStruct.NVIC_IRQChannelSubPriority = 1;          // 子优先级 0-3
    NVIC_InitStruct.NVIC_IRQChannelCmd = ENABLE;
    NVIC_Init(&NVIC_InitStruct);
}
```

【优先级判断规则】

1）抢占优先级高的可以打断低的
2）相同抢占优先级，子优先级高的先执行
3）都相同时，中断向量号小的先执行

【FreeRTOS配置】

```c
// FreeRTOSConfig.h
#define configPRIO_BITS        4        // 4位优先级

// 抢占2位，子2位
#define configMAX_PRIORITIES   4        // 0-3

// 内核使用最低优先级
#define configKERNEL_INTERRUPT_PRIORITY     15

// 系统调用使用较低优先级
#define configMAX_SYSCALL_INTERRUPT_PRIORITY 10
```

29. DMA传输
================================================================================

问题：DMA控制器传输数据需要哪几步配置？为什么DMA可以减轻CPU负担？

答案：

【DMA配置步骤】

1）使能DMA时钟
```c
RCC_AHB1PeriphClockCmd(RCC_AHB1Periph_DMA2, ENABLE);
```

2）设置外设地址
```c
DMA_InitStruct.DMA_PeripheralBaseAddr = (uint32_t)&SPI1->DR;
```

3）设置内存地址
```c
DMA_InitStruct.DMA_Memory0BaseAddr = (uint32_t)rx_buffer;
```

4）设置传输方向
```c
DMA_InitStruct.DMA_DIR = DMA_DIR_PeripheralToMemory;  // 或MemoryToPeripheral
```

5）设置数据长度
```c
DMA_InitStruct.DMA_BufferSize = BUFFER_SIZE;
```

6）设置地址增量
```c
DMA_InitStruct.DMA_PeripheralInc = DMA_PeripheralInc_Disable;
DMA_InitStruct.DMA_MemoryInc = DMA_MemoryInc_Enable;
```

7）设置数据宽度
```c
DMA_InitStruct.DMA_PeripheralDataSize = DMA_PeripheralDataSize_Byte;
DMA_InitStruct.DMA_MemoryDataSize = DMA_MemoryDataSize_Byte;
```

8）设置模式
```c
DMA_InitStruct.DMA_Mode = DMA_Mode_Normal;  // 或Circular
```

9）设置优先级
```c
DMA_InitStruct.DMA_Priority = DMA_Priority_High;
```

10）启动DMA
```c
DMA_Init(DMA2_Stream0, &DMA_InitStruct);
DMA_Cmd(DMA2_Stream0, ENABLE);
```

【DMA减轻CPU负担原理】

1）传统CPU传输
- CPU参与每个数据字节的读写
- 轮询等待外设就绪
- CPU被占用，无法执行其他任务

2）DMA传输
- CPU一次性配置传输参数
- DMA控制器独立完成数据传输
- 传输完成后DMA产生中断通知CPU
- CPU可以并行处理其他任务

【示意图】

```
传统方式：
CPU → 读外设1字节 → 写入内存 → 等外设 → 读外设...（全程占用）

DMA方式：
CPU → 配置DMA参数 → 启动DMA → 执行其他任务
DMA → 自动传输全部数据 → 完成中断 → CPU处理结果
```

30. Flash存储
================================================================================

问题：STM32的Flash擦除按什么为单位？写入时需要注意什么对齐问题？

答案：

【STM32F4 Flash特性】

1）页大小：2KB（2048字节）
2）扇区大小：根据型号不同，F411使用单一扇区（512KB）
3）擦除单位：页（2KB）
4）写入单位：半字（16位）或字（32位）

【Flash擦除】

```c
void Flash_ErasePage(uint32_t page_addr)
{
    // 解锁Flash
    FLASH_Unlock();

    // 清除标志位
    FLASH_ClearFlag(FLASH_FLAG_EOP | FLASH_FLAG_OPERR | FLASH_FLAG_WRPERR);

    // 擦除页
    FLASH_Status status = FLASH_ErasePage(page_addr);

    // 锁定Flash
    FLASH_Lock();
}
```

【Flash写入】

```c
void Flash_WriteData(uint32_t addr, uint32_t *data, uint32_t len)
{
    FLASH_Unlock();

    for (uint32_t i = 0; i < len; i++)
    {
        // 写入半字（16位）
        FLASH_ProgramHalfWord(addr + i*2, data[i]);
    }

    FLASH_Lock();
}
```

【对齐问题】

1）地址对齐
- 半字操作：地址必须是2的倍数
- 字操作：地址必须是4的倍数

```c
// 正确
FLASH_ProgramHalfWord(0x08010000, data);   // 偶数地址
FLASH_ProgramWord(0x08010000, data);       // 4的倍数地址

// 错误（会导致硬件错误）
FLASH_ProgramHalfWord(0x08010001, data);    // 奇数地址
```

2）数据对齐
- 结构体使用 __packed 或对齐属性
- 确保写入的数据大小正确

```c
// 方式1：使用联合体保证对齐
typedef union {
    uint32_t word;
    uint16_t halfword[2];
    uint8_t byte[4];
} data_t;

// 方式2：字节数必须匹配
uint8_t buffer[256];
// 写入时按实际字节数操作
```

【注意事项】

1）擦除前必须先解锁
2）写入前确保已擦除（写入1变为0，无法将0写为1）
3）写入操作以半字或字为单位
4）Flash写入次数有限（通常10万次），注意磨损均衡

31. 心率传感器
================================================================================

问题：MAX30102或类似光学传感器的I2C地址是什么？它的工作流程是怎样的？

答案：

【MAX30102基本特性】

1）I2C地址：7位地址 0x57（8位写地址0xAE，读地址0xAF）

2）主要功能
- 心率血氧监测
- 红外LED + 红光LED双波长
- 内置环境光消除
- 14位ADC，采样率最高4000Hz

【工作流程】

```c
// 初始化
uint8_t MAX30102_Init(void)
{
    uint8_t status;

    // 1. 复位
    MAX30102_WriteReg(REG_MODE_CONFIG, 0x40);  // RESET
    HAL_Delay(10);

    // 2. 配置FIFO
    MAX30102_WriteReg(REG_FIFO_WR_PTR, 0x00);
    MAX30102_WriteReg(REG_FIFO_OVF_COUNTER, 0x00);
    MAX30102_WriteReg(REG_FIFO_RD_PTR, 0x00);
    MAX30102_WriteReg(REG_FIFO_CONFIG, 0x0F);  // 9avg, 4 samples

    // 3. 配置模式（心率模式）
    MAX30102_WriteReg(REG_MODE_CONFIG, 0x02);  // HR mode

    // 4. 配置LED
    MAX30102_WriteReg(REG_LED1_PULSE_AMP, 0x7F);  // 50mA
    MAX30102_WriteReg(REG_LED2_PULSE_AMP, 0x00);  // 关闭

    return 0;
}

// 读取FIFO数据
void MAX30102_ReadFIFO(uint8_t *red, uint8_t *ir)
{
    uint8_t buffer[6];

    // 读取6字节：RED[15:8], RED[7:0], IR[15:8], IR[7:0], reserved, reserved
    MAX30102_ReadReg(REG_FIFO_DATA, buffer, 6);

    *red = (buffer[0] << 8) | buffer[1];
    *ir = (buffer[2] << 8) | buffer[3];
}
```

【关键寄存器】

| 寄存器 | 地址 | 功能 |
|--------|------|------|
| REG_INTR_STATUS_1 | 0x00 | 中断状态 |
| REG_INTR_ENABLE_2 | 0x02 | 中断使能 |
| REG_FIFO_WR_PTR | 0x04 | FIFO写指针 |
| REG_OVF_COUNTER | 0x05 | 溢出计数 |
| REG_FIFO_RD_PTR | 0x06 | FIFO读指针 |
| REG_FIFO_DATA | 0x07 | FIFO数据 |
| REG_MODE_CONFIG | 0x09 | 模式配置 |
| REG_LED1_PULSE_AMP | 0x0C | LED1电流 |
| REG_LED2_PULSE_AMP | 0x0D | LED2电流 |

32. 气压传感器
================================================================================

问题：BMP280气压传感器的数据读取流程是什么？如何计算海平面气压？

答案：

【BMP280基本特性】

1）I2C地址：7位地址 0x76（写地址0xEC，读地址0xED）
- 某些模块可能使用0x77

2）主要参数
- 气压范围：300-1100 hPa
- 精度：±1 hPa
- 温度精度：±1℃
- I2C/SPI接口

【读取流程】

```c
// BMP280校准参数结构体
typedef struct {
    uint16_t dig_T1;
    int16_t  dig_T2;
    int16_t  dig_T3;
    uint16_t dig_P1;
    int16_t  dig_P2;
    int16_t  dig_P3;
    int16_t  dig_P4;
    int16_t  dig_P5;
    int16_t  dig_P6;
    int16_t  dig_P7;
    int16_t  dig_P8;
    int16_t  dig_P9;
} bmp280_calib_t;

bmp280_calib_t calib;

// 初始化
void BMP280_Init(void)
{
    // 读取校准参数
    BMP280_ReadCalib(&calib);

    // 配置传感器
    BMP280_WriteReg(0xF2, 0x01);  // OSRS_T = 1
    BMP280_WriteReg(0xF4, 0x27);  // OSRS_P = 1, mode = normal
}

// 读取气压
int32_t BMP280_ReadPressure(void)
{
    uint8_t data[3];
    int32_t adc_P;

    // 读取气压ADC值
    BMP280_ReadReg(0xF7, data, 3);
    adc_P = (data[0] << 12) | (data[1] << 4) | (data[2] >> 4);

    // 补偿计算（需要校准参数）
    return BMP280_Compensate_P(adc_P, &calib);
}

// 补偿算法（简化版）
int32_t BMP280_Compensate_P(int32_t adc_P, bmp280_calib_t *calib)
{
    int64_t var1, var2, p;

    var1 = ((int64_t)adc_P) - ((int64_t)calib->dig_T1 * 512);
    var1 = var1 * calib->dig_T2 + (var1 * var1 * calib->dig_T3 / 16384);
    var2 = (int64_t)calib->dig_P4 * 131072 + calib->dig_P5 * var1;
    var2 = var2 + (calib->dig_P6 * 4096);
    var1 = (calib->dig_P7 * var1 * var1 / 524288) + (calib->dig_P8 * var1);
    var1 = (1 << 47) + var1;
    p = var2 - ((1 << 33) * 1);
    p = p - (var1 / 536870912);
    p = p / 128;
    p = p + ((1 << 47) * 97);

    return (int32_t)(p / 256);
}
```

【海平面气压计算】

```c
// 公式：P0 = P / (1 - h/44330)^5.255
// P: 测量气压, h: 海拔高度(米), P0: 海平面气压

float BMP280_ToSeaLevelPressure(float pressure, float altitude)
{
    return pressure / pow(1.0f - (altitude / 44330.0f), 5.255f);
}

// 使用示例
float current_pressure = BMP280_ReadPressure() / 256.0f;  // hPa
float sea_level = BMP280_ToSeaLevelPressure(current_pressure, 100); // 假设海拔100米
```

33. 计步算法
================================================================================

问题：加速度传感器的计步原理是什么？如何区分走路和跑步？

答案：

【计步原理】

1）人走路/跑步时产生周期性加速度
- 脚抬起时加速度向上
- 脚落地时加速度向下
- 形成近似正弦波的信号

2）基本流程
```
加速度传感器原始数据
    ↓
    ↓
三轴合成加速度 magnitude = sqrt(x² + y² + z²)
    ↓
    ↓
高通滤波（去除重力影响）
    ↓
    ↓
峰值检测（找波峰）
    ↓
    ↓
峰值验证（阈值判断）
    ↓
    ↓
步数计数
```

【简化实现】

```c
typedef struct {
    int16_t x, y, z;
    float magnitude;
    uint32_t step_count;
    uint8_t last_peak_detected;
    uint32_t peak_timestamp;
    uint16_t peak_threshold;
    uint16_t min_peak_interval;  // 最小峰间隔（防止误计）
} step_counter_t;

void StepCounter_Update(step_counter_t *counter, int16_t x, int16_t y, int16_t z)
{
    // 计算合成加速度（去除重力）
    float raw_mag = sqrt(x*x + y*y + z*z);
    counter->magnitude = raw_mag - 16384;  // 减去1g（16LSB/g）

    // 峰值检测
    uint32_t now = xTaskGetTickCount();

    if (counter->magnitude > counter->peak_threshold &&
        !counter->last_peak_detected &&
        (now - counter->peak_timestamp) > counter->min_peak_interval)
    {
        // 检测到有效步数
        counter->step_count++;
        counter->last_peak_detected = 1;
        counter->peak_timestamp = now;
    }
    else if (counter->magnitude < counter->peak_threshold * 0.5)
    {
        // 回到基线，重置峰值检测
        counter->last_peak_detected = 0;
    }
}
```

【区分走路和跑步】

1）通过频率区分
- 走路：1-2步/秒（60-120步/分）
- 跑步：2-4步/秒（120-240步/分）

2）通过加速度幅度
- 走路：1-2g
- 跑步：2-4g

```c
void DetectActivityType(step_counter_t *counter)
{
    uint32_t peak_count = counter->step_count - counter->last_step_count;
    float avg_magnitude = counter->total_magnitude / peak_count;

    if (avg_magnitude > 30000)  // 约2g
        counter->activity = RUNNING;
    else
        counter->activity = WALKING;

    counter->last_step_count = counter->step_count;
}
```

34. FreeRTOS软件定时器
================================================================================

问题：软件定时器精度受什么影响？它和硬件定时器有什么区别？

答案：

【软件定时器特性】

1）定时器服务任务
- FreeRTOS软件定时器由定时器服务任务处理
- 定时器服务频率由configTICK_RATE_HZ决定
- 默认100Hz，定时精度10ms

2）精度限制
- 定时器精度 = 系统时钟节拍周期
- 不能高于系统节拍频率
- 延迟精度：±1个节拍

【软件定时器vs硬件定时器】

| 特性 | 软件定时器 | 硬件定时器 |
|------|-----------|-----------|
| 精度 | 低（系统节拍） | 高（时钟源） |
| 数量 | 多（无限制） | 少（有限） |
| 资源 | 占用RAM | 占用硬件 |
| 功耗 | 低 | 中 |
| 中断 | 不使用 | 使用 |

【软件定时器使用】

```c
// 定时器句柄
TimerHandle_t timer_handle;

// 定时器回调
void timer_callback(TimerHandle_t xTimer)
{
    static uint32_t count = 0;
    count++;
    // 处理定时任务
}

// 创建定时器
void Create_Timer(void)
{
    timer_handle = xTimerCreate(
        "MyTimer",              // 名称
        pdMS_TO_TICKS(1000),    // 周期1秒
        pdTRUE,                 // 自动重载
        (void*)0,               // ID
        timer_callback          // 回调
    );

    // 启动定时器
    xTimerStart(timer_handle, 0);
}

// 停止定时器
xTimerStop(timer_handle, 0);

// 更改周期
xTimerChangePeriod(timer_handle, pdMS_TO_TICKS(500), 0);
```

【选择建议】

- 简单延时（>10ms）：使用软件定时器
- 精确定时（<10ms）：使用硬件定时器
- PWM输出：必须使用硬件定时器
- 传感器采样：可使用软件定时器

35. 任务通知
================================================================================

问题：FreeRTOS的任务通知（Task Notification）相比队列有什么优势？有什么限制？

答案：

【任务通知特性】

1）直接通知
- 无需创建额外对象
- 效率高，速度快
- 每个任务有一个通知值

2）使用示例
```c
// 发送通知给任务
void Notify_Task(TaskHandle_t task)
{
    // 方法1：发送通知值
    xTaskNotify(task, 0x01, eSetBits);

    // 方法2：带通知值
    xTaskNotify(task, notification_value, eSetValueWithOverwrite);
}

// 任务中接收通知
void Task_Function(void *p)
{
    uint32_t notif_value;

    while(1)
    {
        // 等待通知
        xTaskNotifyWait(0, 0, &notif_value, portMAX_DELAY);

        // 处理通知
        if (notif_value & 0x01)
        {
            // 事件1
        }
        if (notif_value & 0x02)
        {
            // 事件2
        }
    }
}
```

【优势】

1）内存效率
- 不需要队列/信号量对象
- 零额外RAM消耗
- 适合单发送者场景

2）速度
- 无队列创建/删除开销
- 直接操作任务控制块
- 更快的中断处理

【限制】

1）单接收者
- 只能一个任务接收通知
- 不适合多消费者

2）无缓冲
- 通知会被覆盖（除非使用特定模式）
- 不能累积多个通知

3）数据量
- 通知值只有32位
- 需要传输大量数据时不适用

【对比队列】

| 特性 | 任务通知 | 队列 |
|------|---------|------|
| 内存 | 0 | 需要 |
| 速度 | 快 | 慢 |
| 多接收者 | 不支持 | 支持 |
| 数据量 | 32位 | 任意 |
| 缓冲 | 无 | 有 |

```c
#define ST7789_NOP         0x00
#define ST7789_SWRESET     0x01
#define ST7789_RDDID       0x04
#define ST7789_RDSTATS     0x09
#define ST7789_SLPOUT      0x11
#define ST7789_NORON       0x13
#define ST7789_INVOFF      0x20
#define ST7789_INVON       0x21
#define ST7789_DISPOFF     0x28
#define ST7789_DISPON      0x29
#define ST7789_CASET       0x2A
#define ST7789_RASET       0x2B
#define ST7789_RAMWR       0x2C
#define ST7789_PTLAREA     0x30

void ST7789_Init(void)

    ST7789_WriteCommand(ST7789_SWRESET);
    HAL_Delay(150);

    // 2. 退出睡眠

    HAL_Delay(100);
```

39. 电源管理

答案：

【LDO稳压器】

1）原理
- 线性调节，将多余电压转换为热量
- 输出电压 < 输入电压

2）优点
- 电路简单，成本低
- 噪声低，纹波小
- 静态电流小

3）缺点
- 效率低（Vout/Vin）
- 发热量大
- 只能降压

【DCDC转换器】

1）原理
- 开关电源，利用电感/电容储能
- PWM控制输出

2）优点
- 效率高（可达90%+）
- 可升压/降压
- 发热小

3）缺点
- 电路复杂，成本高
- 噪声大，纹波大
- 占用PCB空间大

【智能手表电源设计】

```
┌─────────┐    ┌─────────┐    ┌─────────┐
│  电池   │───→│ DCDC升压 │───→│ LDO     │──→ 3.3V

                       ↓
                ┌─────────┐
                │ 充电IC  │
                │ TP4056  │
                └─────────┘

                 ┌─────────┐
                 │ USB/TC  │
                 │ 供电    │
                 └─────────┘
```

1）电池：3.7V锂聚合物（300-500mAh）
2）DCDC升压：3.7V → 4.0V（屏幕需要）
3）LDO：4.0V → 3.3V（MCU、传感器）

40. CRC校验
================================================================================

问题：CRC校验的原理是什么？在通信中如何保证数据完整性？

答案：

【CRC原理】

1）基本概念
- CRC（Cyclic Redundancy Check）
- 多项式除法
- 检测传输错误

2）常见算法
- CRC-8：多项式0x07
- CRC-16：多项式0x8005
- CRC-32：多项式0x04C11DB7

【STM32 CRC使用】

```c
void CRC_Init(void)
{
    // 使能CRC时钟
    RCC_AHB1PeriphClockCmd(RCC_AHB1Periph_CRC, ENABLE);

    // 复位CRC
    CRC_ResetDR();
}

// 计算32位CRC
uint32_t CRC_Calculate(uint8_t *data, uint32_t len)
{
    uint32_t crc = 0xFFFFFFFF;

    for (uint32_t i = 0; i < len; i++)
    {
        crc ^= data[i];
        for (uint8_t j = 0; j < 8; j++)
        {
            if (crc & 1)
                crc = (crc >> 1) ^ 0xEDB88320;  // CRC-32多项式
            else
                crc >>= 1;
        }
    }

    return ~crc;
}

// 使用硬件CRC
uint32_t CRC_Calculate_Hardware(uint8_t *data, uint32_t len)
{
    CRC_ResetDR();

    for (uint32_t i = 0; i < len; i++)
    {
        CRC->DR = data[i];
    }

    return CRC->DR;
}
```

【通信中使用】

```c
// 发送端
void Send_Data(uint8_t *data, uint32_t len)
{
    uint32_t crc = CRC_Calculate(data, len);

    // 发送数据和CRC
    UART_Send(data, len);
    UART_Send((uint8_t*)&crc, 4);
}

// 接收端
bool Receive_Data(uint8_t *data, uint32_t len)
{
    uint8_t crc_recv[4];
    uint32_t crc_calc, crc_recv_val;

    UART_Receive(data, len);
    UART_Receive(crc_recv, 4);

    crc_calc = CRC_Calculate(data, len);
    crc_recv_val = *(uint32_t*)crc_recv;

    return (crc_calc == crc_recv_val);
}
```

42. 延时函数
================================================================================

问题：HAL_Delay()函数是如何实现的？为什么不能用在中断中？

答案：

【实现原理】

```c
// 基于SysTick的中断实现
volatile uint32_t uwTick;

void HAL_Init(void)
{
    // 配置SysTick为1ms中断
    SysTick_Config(SystemCoreClock / 1000);
}

void SysTick_Handler(void)
{
    uwTick++;
}

__weak void HAL_Delay(uint32_t Delay)
{
    uint32_t tickstart = HAL_GetTick();
    uint32_t wait = Delay;

    if (wait < 0xFFFFFFFFU)
    {
        while ((HAL_GetTick() - tickstart) < wait)
        {
            // 等待
        }
    }
}
```

【不能用在中断的原因】

1）SysTick优先级
- SysTick中断可能被其他更高优先级中断打断
- 造成延时不准

2）阻塞特性
- HAL_Delay()是阻塞函数
- 在中断中使用会阻塞其他中断

3）建议
- 中断中使用定时器计数
- 或使用其他非阻塞延时

```c
{
    static uint8_t cnt = 0;

    switch (key_state)
    {
        case IDLE:
            if (Key_Pressed())
            {
                key_state = DEBOUNCE;
                cnt = 0;
            }
            break;

        case DEBOUNCE:

                if (Key_Pressed())

                    key_state = IDLE;
            }
            break;

            break;
```

答案：

【时钟源】

1）HSI（High Speed Internal）
- 16MHz内部RC振荡器
- 不精确，受温度影响

2）HSE（High Speed External）
- 外部晶振（通常8MHz）
- 精确，稳定

3）PLL（锁相环）
- 倍频HSI或HSE
- 可达168MHz

4）LSI（Low Speed Internal）
- 32KHz低速时钟
- 用于RTC/看门狗

5）LSE（Low Speed External）
- 32.768KHz外部晶振
- 用于RTC

49. FreeRTOS启动
================================================================================

问题：FreeRTOS的调度器是如何启动的？vTaskStartScheduler()函数做了什么？

答案：

【启动流程】

```c
int main(void)
{
    // 硬件初始化
    HAL_Init();
    SystemClock_Config();

    // 创建任务
    xTaskCreate(Task1, "Task1", 256, NULL, 1, NULL);
    xTaskCreate(Task2, "Task2", 256, NULL, 2, NULL);

    // 启动调度器（永不返回）
    vTaskStartScheduler();

    // 不会执行到这里
    while(1);
}
```

【vTaskStartScheduler()做了什么】

1）创建IDLE任务
2）配置SysTick作为系统节拍
3）使能中断
4）启动第一个任务
5）进入调度循环

53. I2C从设备地址
================================================================================

问题：I2C从设备的7位地址和8位地址有什么区别？如何转换？

答案：

【区别】

- 7位地址：去掉读/写位的纯地址
- 8位地址：包含读/写位（最后一位）

【转换】

```c
// 7位地址 → 8位地址
uint8_t addr_7bit = 0x57;
uint8_t addr_write = addr_7bit << 1;      // 0xAE
uint8_t addr_read = (addr_7bit << 1) | 1; // 0xAF

// 8位地址 → 7位地址
uint8_t addr_8bit = 0xAE;
uint8_t addr_7bit = addr_8bit >> 1;      // 0x57
```

54. SPI片选
================================================================================

问题：SPI从设备的片选（CS）信号有什么作用？为什么需要它？

答案：

【作用】

- 片选（Chip Select / Slave Select）
- 选择指定的从设备进行通信
- 同一总线上可连接多个从设备

【原理】

```
    SCK ──────────────────────┬─────────────────────
    MOSI ──────────────────────┼─────────────────────
    MISO ──────────────────────┼─────────────────────
    CS1  ─────┐                │                (设备1)
              └────────────────┘
    CS2  ──────────────────────┬──────┐          (设备2)
                               └──────┘
```

- CS低电平：选择该设备
- CS高电平：未选中，忽略总线信号
- 每次通信前拉低对应设备的CS

```c
void USART1_IRQHandler(void)

}

__weak void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    // 用户可重定义
}
```

56. Bootloader
================================================================================

问题：简述STM32的Bootloader概念，程序是如何从Bootloader跳转到应用程序的？

答案：

【Bootloader概念】

- Bootloader：引导程序
- 负责初始化硬件、选择启动方式
- 可用于升级应用程序

【跳转实现】

```c
typedef void (*jump_func)(void);

void JumpToApp(uint32_t app_addr)
{
    // 1. 检查栈顶地址是否有效
    if (((*(__IO uint32_t*)app_addr) & 0x2FFE0000) == 0x20000000)
    {
        // 2. 获取复位向量
        jump_func JumpToApplication = (jump_func)(*(__IO uint32_t*)(app_addr + 4));

        // 3. 设置栈指针
        __set_MSP(*(__IO uint32_t*)app_addr);

        // 4. 跳转到应用
        JumpToApplication();
    }
}
```

57. 编译链接
================================================================================

问题：链接脚本（.ld文件）的作用是什么？为什么要定义Flash和RAM的起始地址？

答案：

【链接脚本作用】

1）定义内存布局
- 哪些地址范围是Flash
- 哪些地址范围是RAM

2）分配段
- 代码段(.text)放到Flash
- 数据段(.data)复制到RAM
- 未初始化段(.bss)清零

【STM32F411示例】

```c
/* 链接脚本关键部分 */
MEMORY
{
  FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 512K
  RAM (rwx)   : ORIGIN = 0x20000000, LENGTH = 128K
}

SECTIONS
{
  .text :
  {
    . = ALIGN(4);
    *(.text)
    *(.text*)
    . = ALIGN(4);
  } >FLASH

  .data :
  {
    _sdata = .;
    *(.data)
    _edata = .;
  } >RAM AT>FLASH

  .bss :
  {
    _sbss = .;
    *(.bss)
    *(COMMON)
    _ebss = .;
  } >RAM
}
```
